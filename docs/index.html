Instance tree25 tools+
  • changes_listRead

    List recorded UAI property/attribute changes and Undo status. Other game effects are outside this history.

  • changes_readRead

    Inspect recorded before/after values for one supported game-change batch.

  • changes_undoWrite

    Undo one recorded property/attribute batch. Rechecks every target/value and never overwrites a conflicting newer edit.

  • code_extract_sourceWrite

    Extract a UTF-8 byte range from an immutable source snapshot into a separate editable document. Opening or extracting never runs source.

  • code_open_sourceWrite

    Open a script/file/capture as a source snapshot in the shared Code workspace. Large source stays in a bounded reader. Never overwrites a modified document or executes source.

  • explorer_childrenRead

    Read a bounded child page by exact parent handle or logical root (nil/bookmarks). Cursors reject changed branches.

  • explorer_exportWrite

    Export explicitly selected object metadata to a verified user file. Model export and full-place saving are not provided.

    Requires fs
  • explorer_propertiesRead

    Read supported properties, attributes or tags for exact handles or shared selection. Returns a bounded page and an expiring snapshot_id for guarded edits; large values are labelled previews.

  • explorer_searchRead

    Search by literal name, class, tag and subtree with bounded cooperative traversal and snapshot pages.

  • explorer_selectWrite

    Explicitly change shared Explorer selection (maximum 20). Existing selection requires expected_revision. focus optionally opens the native workspace.

  • explorer_stateRead

    Read native Explorer selection, root handles, metadata coverage and capabilities. Does not scan or change selection.

  • instance_attributeWrite

    Read or write an attribute on an instance. Omit value to read.

  • instance_cloneWrite

    Clone an instance. The copy keeps its children.

  • instance_createWrite

    Create an instance detached, validate/apply properties, then parent it. Legacy property maps use sorted property names. Failed setup destroys only the new owned instance.

  • instance_destroyHigh impact

    Destroy an instance and everything under it. This cannot be undone.

  • instance_edit_manyWrite

    Apply ordered typed property/attribute/tag operations with expected values or an observed snapshot. Preflight conflicts produce zero writes. Property/attribute changes share Game changes Undo.

  • instance_findRead

    Search a subtree for instances by name and/or class. Stops when the requested result count is reached. For selected properties and paginated results, use instance_query.

  • instance_getRead

    Read an instance's properties, attributes and tags. Do this before setting anything.

  • instance_get_manyRead

    Inspect up to 20 known instance paths at once. Select only the properties and attributes needed; compact class defaults are used otherwise. Missing paths do not discard successful reads.

  • instance_parentWrite

    Reparent an instance.

  • instance_queryRead

    Find instances and read selected properties/attributes in one call. Name is a case-insensitive substring; class uses IsA. Stops as soon as a page fills, without collecting the entire subtree. Search is capped at 20,000 nodes.

  • instance_result_readRead

    Read bounded retained detail from a large result in this tool group. Follow returned path arrays and offsets; expires after five minutes.

  • instance_setWrite

    Set one property on one instance. The value is converted to the property's existing type, so 'Size' takes '4, 1, 2' on a part and '0, 200, 0, 40' on a GUI frame.

  • instance_taggedRead

    List instances carrying a CollectionService tag, or list every tag in use.

  • instance_treeRead

    List the children of an instance as an indented tree. Start here when exploring an unfamiliar game.

Code5 tools+
  • check_luauRead

    Check Luau syntax without executing code or changing the game. Provide inline 'code' or a saved file 'path', not both. Prefer path for scripts you wrote or edited so their source need not be sent again. Returns compile errors for correction before run_luau.

    Requires exec
  • run_luauHigh impact

    Run bounded Luau on the local client. Provide inline source in 'code', or 'path' to run a workspace file directly without reading it back first. Captures print/warn, tables and all return values; waits for functions started with task.spawn/defer/delay. Stop or the deadline cancels managed tasks. Loop checkpoints yield automatically. Prefer a specific tool when one exists. This is not a security sandbox; dynamically loaded code and engine calls can bypass cooperative guards.

    Requires exec
  • script_listRead

    List script instances in the place, with their paths. Useful for finding where behaviour lives before reading it.

  • script_result_readRead

    Read bounded retained detail from a large result in this tool group. Follow returned path arrays and offsets; expires after five minutes.

  • script_sourceRead

    Read a script's source. Works when the host can read or decompile it; many live scripts cannot be read at all.

Files9 tools+
  • file_appendWrite

    Append up to 2 MiB to a workspace file, creating it if needed. Prefer small additions.

    Requires fs
  • file_deleteHigh impact

    Delete a file or folder from your workspace. This cannot be undone.

    Requires fs
  • file_editWrite

    Replace exact text in a workspace file without rewriting the whole file. Read it first. Refuses missing or ambiguous matches unless replace_all is true, and refuses an edit if the file changed while it was being prepared. Files and edited output are limited to 2 MB.

    Requires fs
  • file_edit_manyWrite

    Apply up to 20 exact edits to one workspace file in one write. Edits are evaluated in order. All must validate before writing; refuses stale contents. Empty new_text deletes. File/output limit 2 MB.

    Requires fs
  • file_listRead

    List files in your workspace (files/, inside the agent folder).

    Requires fs
  • file_readRead

    Read a contiguous slice of a workspace file or saved paste. The result includes a continuation offset when more remains.

    Requires fs
  • file_read_manyRead

    Read up to 12 workspace files or saved pastes in one call, sharing the result budget. Each slice includes continuation offsets. Individual failures preserve other results.

    Requires fs
  • file_searchRead

    Find literal text across workspace files or saved pastes in one call. Returns matching lines, byte offsets and a continuation cursor. Searches subfolders; skips binary/files over 2 MB. Bounds directory, file and byte scans.

    Requires fs
  • file_writeWrite

    Create a workspace file or replace most of its content (up to 2 MiB per call). Parent folders are created. For existing files, prefer file_edit or file_edit_many for targeted changes. Build large new scripts in small sections with sequential file_write then file_append calls.

    Requires fs
Agent12 tools+
  • agent_followupWrite

    Send another message to a subagent that has already reported, keeping everything it found. Use this instead of dispatching a fresh one whenever you want more from the same investigation: 'you stopped at the step limit, carry on', 'now check X as well', 'quote that line verbatim'. It is far cheaper than a new dispatch, which would have to rediscover what this one already knows. Takes the id from the report. Blocks until it answers again.

  • ask_userRead

    Ask the user one question and wait for their answer. Use when a request is genuinely ambiguous -- two ways to read it, a choice of targets, a preference you cannot infer -- and answering it wrong would waste work. Offer concrete options when the plausible answers are few; omit them for an open question. The answer comes back as this call's result. You cannot ask from a subagent.

  • conversation_listRead

    List this user's other conversations for review, most recent first, each with its id, title, place, age, size and opening request. Use it to triage which past thread is relevant, then read that one with conversation_read. Untouched empty chats are omitted; the current conversation is marked and does not need reading. Query filters on the title or the opening request.

  • conversation_readRead

    Read one of this user's other conversations by id (from conversation_list or conversation_search). Condensed by default: the whole thread with long turns shortened and tool runs collapsed, so a review costs one bounded read. Pass full=true for the verbatim transcript in UTF-8-safe byte slices, following nextOffset for the rest. Use it after a list or search points at a relevant thread, so you carry forward what was decided instead of re-deriving or re-asking it.

  • conversation_searchRead

    Search this user's other conversations for something they or the agent said earlier. Use it when the current request refers to earlier work -- 'like last time', 'the script you fixed', 'my usual setup' -- and the facts are not in this conversation. Returns the matching lines with which conversation they came from and its [id]; read the whole thread with conversation_read. This conversation is not searched; you already have it.

  • dispatch_agentWrite

    Hand a self-contained investigation to a subagent with its own context, and get back a written report. Use for wide searches, repetitive inspection, or anything that would otherwise fill this conversation with tool output. Call it several times in one step to run that many subagents at once: they work in parallel and you wait once, not once each. A subagent cannot ask questions, so state the task completely. The call blocks until its report is ready. The report carries an id you can send follow-ups to with agent_followup, so ask for the first slice of a big job rather than describing all of it.

  • memory_forgetRead

    Delete one remembered key.

  • memory_readRead

    List everything currently remembered, or read one key.

  • memory_writeRead

    Save a durable fact about this user or project under a short key. Survives context compaction and restarts. Use for preferences, paths and goals, not for transcript chatter.

  • todo_readRead

    Read the current task list.

  • todo_writeRead

    Replace the task list with the full set of items and their statuses. Use for any job with more than about three steps; keep exactly one item active.

  • waitRead

    Pause for a few seconds before continuing, to let something in the game settle or a change take effect.

  • auto_replyWrite

  • chat_botWrite

Maintains its own conversation memory and replies to new player messages without keeping this agent turn open.   • chat_historyRead

  • chat_loop_statusRead

  • chat_sendWrite

    Send a message into Roblox chat. Reports a failure if no channel is available.

  • quiz_botWrite

    Host a quiz in Roblox chat: ask questions, detect the first correct player answer, keep scores, reveal unanswered answers, and repeat. Supply questions and answers. Returns a managed loop ID.

Infinite Yield10 tools+
  • iy_cmdWrite

    Run an Infinite Yield command by its command string, exactly as typed into IY's own bar: 'speed 100', 'noclip', 'tp PlayerName', 'esp players'. Supports IY's repeat prefixes ('5^speed 100', 'inf^0.5^esp'). Check iy_status first; when the setting is on but IY is not loaded, this call loads it.

  • iy_cmdsRead

    List Infinite Yield commands, optionally filtered by a keyword or limited to one plugin's commands. Shows names, aliases, plugin origin, and argument signatures and descriptions when IY exposes them. Use it before iy_cmd to check syntax.

  • iy_controlWrite

    Inspect and configure Infinite Yield's saved events, keybinds, aliases, waypoints and settings. Inspect first for current 1-based binding indexes, event fields and defaults. Supports OnExecute, OnSpawn, OnDied, OnDamage, OnKilled, OnJoin, OnLeave and OnChatted. Event commands can use $1/$2 arguments; native IY ignores commands containing 'plugin'. Edits refresh IY's editor and request its normal save. Waypoints default to the current place. Use iy_cmd to execute commands, iy_plugin_write for plugins/custom events. stop_loops sends breakloops.

  • iy_playersRead

    Resolve an IY selector to concrete names in the live server (read-only). Keywords: all, others, me, random, #<n>, %<team>, allies, enemies, team, nonteam, friends, nonfriends, guests, bacons, age<n>, nearest, farthest, group<id>, alive, dead, rad<n>, cursor, npcs. Supports + include/- exclude, comma-separated lists, and @name for username-only prefix matching. Uses the running IY's selector behavior; resolve targets before iy_cmd.

  • iy_plugin_installWrite

    Install a plugin from the Infinite Yield store: downloads its .iy file, saves it to the workspace and registers it with the running Infinite Yield, whose commands then work through iy_cmd. Accepts the plugin name ('dexrecontinued'), a filename ('dexrecontinued.iy') or the store id.

  • iy_plugin_readRead

    Read an authored .iy plugin from the executor workspace, or omit plugin to get a multi-command template. Follow nextOffset for long sources. Use this before updating a plugin with iy_plugin_write.

  • iy_plugin_searchRead

    Search the Infinite Yield community plugin store (iyplugins.pages.dev, several hundred plugins) by name, author or filename. Returns matches with their authors. Use it when the user asks for a feature core IY does not have, then install with iy_plugin_install.

    Requires http
  • iy_plugin_uninstallWrite

    Remove a plugin: unregisters its commands from Infinite Yield and deletes its .iy file. Accepts the name with or without the .iy ending.

  • iy_plugin_writeHigh impact

    Create or update a custom Infinite Yield .iy plugin. Get the template with iy_plugin_read. Source may declare shared locals/globals above local Plugin, and must return a table with PluginName, PluginDescription and Commands. Each command has ListName, Description, Aliases and Function(args, speaker). Checks syntax before saving. By default executes setup once, validates the returned table and loads/reloads it through IY, returning actual registered command names. load=false only saves syntax-checked source. Set overwrite=true to replace an existing file. Reloading replaces commands; plugin-owned event connections or loops need cleanup in the plugin's own setup/unload command.

    Requires fs, exec
  • iy_statusRead

    Report Infinite Yield: the Settings mode, whether it is loaded, how it was obtained (already running, or loaded by this client), the command count and prefix. Call this before iy_cmd when you do not know whether IY is available.

Project Gravity13 tools+
  • gravity_configureWrite

    Change Gravity engine, formation, interface, performance and Part Control panel defaults using native names. Validates the whole batch, applies native effects, refreshes controls and requests a save. PartCtl* are panel defaults; use gravity_part_control to change selected parts. Read gravity_status first.

    Requires gravity
  • gravity_controlWrite

    Control Gravity using native handlers: start/recenter (defaults to your character), stop and release parts, pause/resume, enable/disable, reroll, reset_settings (all engine/shape settings and keybinds to defaults), or launch/charge a manually controlled Slingshot.

    Requires gravity
  • gravity_favoriteWrite

    Add/remove shape favorites or clear all favorites in Gravity's native selector. List favorite flags with gravity_shapes. Saves by default; persist=false keeps this session only.

    Requires gravity
  • gravity_keybindWrite

    Set or clear one native Gravity hotkey on desktop or mobile. Provide action or shape, and a Roblox KeyCode name (e.g. E, F5); key="" unbinds it. Refuses conflicts with other core/shape bindings. Read current keybinds in gravity_status.

    Requires gravity
  • gravity_launchHigh impact

    Download and run the official Project Gravity loader in this client, then report the live status. Use this when gravity_status shows Gravity is not loaded. If Gravity is already connected this reports that without reloading; pass force=true to re-run the loader, which reloads Gravity and releases held parts. This fetches and executes remote code from the Project Gravity repository.

    Requires http, exec
  • gravity_part_controlWrite

    Use native Gravity Part Control. select/add/deselect require IDs from gravity_parts; clear deselects without releasing overrides. select_all/select_overridden/invert replace the selection, capped at Gravity's native 512 parts. assign/move/ride/physics/release affect the current selection. assign supports pin/manual/shape/normal; a supplied position is shared by all assigned parts. move preserves group offsets and sets manual targets: use position for the group's center or offset for relative movement. physics replaces overrides; {} restores inheritance. release_all clears even unselected overrides. Selection and overrides are live session state.

    Requires gravity
  • gravity_partsRead

    Inspect held Gravity parts with stable session-scoped IDs, paths, positions, selections and overrides. Paginated and sorted by claim ID; read nextOffset for more. IDs expire when the part is released or Gravity reloads.

    Requires gravity
  • gravity_plugin_readRead

    Read Gravity's module guide/template (omit plugin), or real local/official shape source. Bounded source slices include continuation offsets. Read the guide before authoring a plugin; section=template returns a working module.

  • gravity_plugin_writeHigh impact

    Create/update a real GravityShapes/<plugin>.lua file from a saved source path or inline source. Prefer path for long scripts. Checks syntax and verifies disk contents. By default evaluates setup once with a deadline, validates f2/Controls and registers the module in Gravity. load=false saves without executing. overwrite=true is required for replacement. Does not select an inactive shape; existing active shapes reload with cleanup. Plugin callbacks need their own cleanup.

    Requires fs, exec
  • gravity_shapeWrite

    Select a Gravity shape, configure its control keys, or press one real Button. Inspect gravity_shapes(name=...) first. Values use stored units (display divided by Div). Buttons require that shape to be selected and never become settings.

    Requires gravity
  • gravity_shapesRead

    List the live Gravity shape catalog, or pass name to inspect a shape's real control keys, values, buttons and stored-unit slider ranges. No hardcoded catalog.

    Requires gravity
  • gravity_statusRead

    Inspect the connected Project Gravity engine, selected shape, targets, held part count and settings. Reports when Gravity is not loaded.

  • gravity_targetWrite

    Set Gravity's anchor to yourself or all players, add/remove a specific target, or clear targeting. Ambiguous player names are refused. Preserves the native Targets table.

    Requires gravity

  • remote_result_readRead

  • remotes_listRead

A few useful details

Before you jump in.

Does every tool work in every executor?+

UAI detects the host's capabilities. File access, code execution, virtual input, and other tools depend on the functions your host provides. Tools that need missing capabilities are omitted from the model's available tools.

What happens when I press Stop?+

Stop cancels the current agent turn and managed Luau tasks cooperatively. Execution has a default 10-second deadline, adjustable up to 60 seconds. Native engine calls, dynamically loaded code, and persistent event callbacks can fall outside that cancellation. Changes that already happened are not rolled back.

Where do my data and requests go?+

UAI stores settings, conversations, and activity in your executor's workspace when filesystem support is available. Your configured inference provider receives the context and tool results used to answer a request. Provider keys belong in UAI's settings, never on this showcase site.

Is Project UAI free to use?+

Project UAI is open source under the MIT license. Your model provider sets its own pricing and availability.
